# python-adk-runtime — AI 維護指南（llm.txt）

此檔規範 AI 與協作者在維護 Python ADK Runtime（`python-adk-runtime/`）的流程，與 `AGENT.md`、`spec.md` 一致。

## 範圍與原則
- 嚴格遵守 Google ADK 標準：Agent、FunctionTool、Runner、SessionService
- 與 Go 平台解耦：僅透過 gRPC ToolBridge（RemoteTool）或 HTTP 互通
- 任何跨語言介面或型別變更先改 `contracts/`（SSOT），再回此專案對齊生成碼與相依
- 所有註解與文件使用繁體中文

## 必守規範（與 AGENT.md 對齊）

### Agent vs Tool 黃金準則
1. **Agent 職責（決策層）**：WHY（為什麼）、WHAT（做什麼）、WHEN（何時做）
   - 決策制定、工作流編排、知識整合、業務邏輯處理
   - **重要限制**：Agent 不直接操作數據，所有數據查詢、API 調用、文件生成都通過 Tool
2. **Tool 職責（執行層）**：HOW（如何做）、WHERE（在哪做）、WITH（用什麼）
   - 具體執行、數據操作、外部系統集成
   - **重要特性**：Tool 不包含業務邏輯，是無狀態、冪等、原子性的執行單元

### 技術實現規範
3. **ADK 標準**：使用 `FunctionTool` 包裝函式，Agent 使用 Root + Sub-Agents 架構
4. **RemoteTool**：以 `grpc.aio` 連 ToolBridge；端點由 `DETECTVIZ_TOOLBRIDGE_ADDR` 指定；傳遞 `traceparent/tracestate`
5. **Session State**：透過 ADK `ToolContext` 管理狀態，不使用全域變數
6. **設定載入**：`detectviz_adk/config/loader.py` 與 Go Loader 對齊搜尋序與環境覆蓋
7. **模組卡**：新增/擴增元件需附 `module.card.json` 並通過 `contracts/tools/validate_module_card.py`
8. **安全**：Python 端不持有雲端寫入憑證；外部副作用集中於 Go 插件（Tools）
9. **SSOT 契約**：不得修改 `contracts/gen/**` 生成碼；如需型別/欄位調整，回到 `contracts/`

### MVP Phase 3 專用規範
10. **事後複盤聚焦**：當前開發重點為 postmortem_orchestrator ADK Agent 團隊
11. **混合架構決策**：業務邏輯（Python）+ 高性能查詢（Go）+ gRPC 橋接
12. **程式碼品質**：類型標註、docstring、測試覆蓋率 > 90%、錯誤處理完善

## 允許/禁止

### 允許的操作
- 新增 ADK Agent、FunctionTool、Runner（以 RemoteTool 呼叫 Go 插件）
- 實現符合 MVP Phase 3 的事後複盤功能
- 在 Python 端進行決策邏輯和業務流程編排
- 使用 RemoteTool 調用 Go 端的高性能數據查詢

### 嚴格禁止的操作
- **違反職責分離**：Agent 直接執行數據查詢、文件操作、API 調用
- **在 Python 端直接查詢外部系統**：如直接連接 InfluxDB、資料庫等
- 跨越 ADK 邏輯邊界、直連雲端憑證、繞過 Loader 讀寫設定
- 提交大型二進位、使用非 ADK 標準的代理架構
- 修改已定義的 contracts/ 契約（除非經過 SSOT 更新流程）

## 變更流程
1. 規劃：是否涉及 SSOT？若是，先改 `contracts/` 並 `buf lint && buf generate`。
2. 實作：使用 templates 腳手架建立元件；補 README 與最小測試。
3. 驗證：
```bash
# 啟動 Go ToolBridge（另窗）
# detectviz plugin serve --config ./go-platform/configs/config.yaml --http-demo --http-demo-listen :7777

# 執行 Python 端範例/測試（以虛擬環境）
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python server.py   # 或對應入口
```
4. 記錄：在根 `README.md`、文件站對應章節同步更新。
5. PR：說明 SSOT 影響、端到端流程（RemoteTool 呼叫、trace 傳遞）、是否更新文件。
