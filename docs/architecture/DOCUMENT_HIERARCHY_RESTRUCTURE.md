# 文檔層級重構建議

## 🎯 當前問題

**spec.md** 和 **sre-services-map.md** 存在嚴重的定位模糊問題：

1. **內容重疊**：兩者都包含架構設計、技術實現、業務邏輯
2. **層級混亂**：聲稱的層級關係與實際內容不符
3. **職責不清**：讀者無法明確知道該查閱哪個文檔

## 🏗️ 重構方案

### 方案 A：合併重構（推薦）

#### 1. 保留 sre-services-map.md 作為**唯一架構憲法**
```markdown
# sre-services-map.md
- 職責：業務邏輯 + 架構決策 + 技術標準
- 內容：SRE三階段 + Agent協作模式 + 技術架構選型
- 讀者：所有開發者（AI + 人類）
- 層級：頂層架構文檔
```

#### 2. 將 spec.md 重構為**實施指南**
```markdown
# implementation-guide.md
- 職責：具體實施步驟 + 配置範例 + 開發工具
- 內容：目錄結構 + 啟動命令 + 配置檔案
- 讀者：實施開發者
- 層級：操作指南
```

#### 3. 新的文檔層級
```bash
sre-services-map.md          # 架構憲法（業務+技術決策）
         ↓
AGENT.md                     # AI協作規範
         ↓ 
docs/guides/IMPLEMENTATION_GUIDE.md  # 實施指南
         ↓
各模組 llm.txt               # 具體執行檢查清單
```

### 方案 B：職責分離（替代方案）

#### 1. sre-services-map.md → 純業務架構
- **專注**：SRE三階段、Agent協作模式、業務決策
- **移除**：技術實現細節、配置範例、啟動命令

#### 2. spec.md → 純技術規格
- **專注**：技術架構、API設計、系統配置
- **移除**：業務邏輯描述、Agent協作模式

#### 3. 新增 system-architecture.md
- **職責**：連接業務和技術，提供整體系統視圖

## 📋 重構執行計劃

### Phase 1: 內容分析和歸類
1. 識別重複內容
2. 按職責分類所有內容段落
3. 確定保留/移動/刪除的內容

### Phase 2: 重構執行
1. 重組 sre-services-map.md 為完整架構憲法
2. 精簡 spec.md 為純實施指南
3. 更新所有引用鏈接

### Phase 3: 驗證和優化
1. 確保無內容遺失
2. 驗證文檔層級邏輯清晰
3. 更新 AGENT.md 中的引用關係

## 🎯 推薦執行

**建議採用方案 A（合併重構）**，理由：

1. **減少維護負擔**：單一架構文檔，避免同步問題
2. **提高可讀性**：完整的上下文，減少跳轉
3. **符合 SSOT 原則**：一個概念一個地方描述
4. **降低認知負荷**：開發者只需理解一個核心文檔

## ⚡ 快速修復建議

如不進行大規模重構，至少應該：

1. **明確文檔邊界**：在每個文檔開頭明確說明職責範圍
2. **消除重複內容**：選擇一個文檔作為權威，其他文檔引用
3. **統一層級關係**：確保聲稱的層級與實際內容一致
4. **標準化引用**：使用一致的引用格式

---

**結論**：當前的 spec.md 和 sre-services-map.md 確實存在定位模糊問題，建議按方案 A 進行重構，建立清晰的文檔職責邊界。
